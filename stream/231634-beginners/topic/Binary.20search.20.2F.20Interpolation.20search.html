notramo (Nov 06 2026 at 11:06):

List underlying data structure: Is it ok to think of a List as a span on a contiguous memory? Are lst.take_first(n) and its drop counterpart equivalent to taking a subspan (slice)?

Yes. Unlike in most functional languages, Roc List is actually an array under the hood, not a linked list. The optimizer slices into that backing array when possible, so take/drop first/last and get is very fast. For deleting an elem in the middle, there's List.drop_swap, but it's only usable when ordering is not important. On the other hand, append has worse performance, because it sometimes need to reallocate a new backing array, and prepend has even worse, because it needs to memcpy the items in addition to sometimes reallocating (except if the list had a drop_first called earlier, because in that case it has empty space before the first item).

notramo (Nov 06 2026 at 11:06):

See also List.prefetched and List.reserve for performance optimizations. Note that these are pure functions from the viewpoint of the program, and only affect the performance of the runtime, not the logic of your program, so you can freely experiment with putting these in various places.

Aliases are great. I changed the code to make use of them. But since I can't extend built-in types, I changed interpolation_search to expect an interpolation_factor : a, a, a -> F32 function as the first parameter. I understand that Roc has no currying, but it still "feels right" to make this param the first one (since its most likely to be bound, as I demonstrate in the tests).

InterpolationSearch :: [].{

    a.Comparable :  where [a.is_lt : a, a -> Bool, a.is_lte : a, a -> Bool]

    interpolation_search : (a, a, a -> F32), List(a), a -> U64 where [a.Comparable]
    interpolation_search = |interpolation_factor, lst, target| match lst {
        [] => 0
        [only] if only < target => 1
        [_] => 0
        [first, ..] if target <= first => 0
        [.., last] if last < target => lst.len()
        [first, .., last] => {
            f = interpolation_factor(first, target, last)
            mid_idx = ((lst.len() - 1).to_f32() * f).to_u64_wrap()
            match lst.get(mid_idx) {
                Ok(mid) => if !(mid < target) {
                    interpolation_search(interpolation_factor, lst.take_first(mid_idx), target)
                } else {
                    interpolation_search(interpolation_factor, lst.drop_first(mid_idx + 1), target) + mid_idx + 1
                }
                _ => crash "`interpolation_factor` must return an F32 value in [0.0, 1.0] range."
            }
        }
    }

    # Tests

    ## Dec
    interpolation_factor_dec = |a, b, c| (b - a) / (c - a)
    interpolation_search_dec = |lst, target| interpolation_search(interpolation_factor_dec, lst, target)

    expect interpolation_search_dec([1.0.F32, 2.0, 3.0], 0.0) == 0
    expect interpolation_search_dec([1.0.F32, 2.0, 3.0], 1.0) == 0
    expect interpolation_search_dec([1.0.F32, 2.0, 3.0], 2.0) == 1
    expect interpolation_search_dec([1.0.F32, 2.0, 3.0], 3.0) == 2
    expect interpolation_search_dec([1.0.F32, 2.0, 3.0], 4.0) == 3

    ## I32
    interpolation_factor_i32 = |a, b, c| (b - a) / (c - a)
    interpolation_search_i32 = |lst, target| interpolation_search(interpolation_factor_i32, lst, target)

    expect interpolation_search_i32([1, 2, 3, 3, 3, 4, 5, 6], 0) == 0
    expect interpolation_search_i32([1, 2, 3, 3, 3, 4, 5, 6], 3) == 2

    ## Custom type
    Item := { val : F32 }.{
        is_lt : Item, Item -> Bool
        is_lt = |a, b| a.val < b.val

        is_lte : Item, Item -> Bool
        is_lte = |a, b| a.val <= b.val
    }
    interpolation_factor_item : Item, Item, Item -> F32
    interpolation_factor_item = |a, b, c| (b.val - a.val) / (c.val - a.val)
    interpolation_search_item = |lst, target| interpolation_search(interpolation_factor_item, lst, target)

    test_list : List(Item)
    test_list = [{ val: 1.0 }, { val: 2.0 }, { val: 3.0 }]
    expect interpolation_search_item(test_list, Item.{ val: 2.0 }) == 1
}

Anton (Nov 08 2026 at 18:26):

Hi @Vanand Gasparyan,

I had Claude Opus 5.5 draft a reply which has been reviewed and edited by me:

where clauses get you most of what you're after: any type that has the right methods fits automatically, including your own types, and there's no "impl" to declare.

Here's a shape that covers all builtin numbers and also your timestamp idea:

InterpolationSearch :: [].{
    a.Comparable : where [a.is_lt : a, a -> Bool]

    # Fully general: the caller provides the factor.
    search_with : List(a), a, (a, a, a -> F64) -> U64 where [a.Comparable]
    search_with = |lst, target, factor| ... # your current body, using to_f64

    # Builtin numbers, plus any of your own types with is_lt, minus and to_f64.
    search : List(a), a -> U64 where [a.Comparable, a.minus : a, a -> d, d.to_f64 : d -> F64]
    search = |lst, target| search_with(lst, target, |lo, x, hi| x.minus(lo).to_f64() / hi.minus(lo).to_f64())

    expect search([1, 2, 3, 3, 3, 4, 5, 6], 3) == 2
    expect search([1.5, 2.5, 3.5], 2.5) == 1

    # Timestamp-like: `minus` returns a different type, no factor function needed
    expect {
        Duration := { secs : I64 }.{
            to_f64 = |d| d.secs.to_f64()
        }
        Timestamp := { secs : I64 }.{
            is_lt = |a, b| a.secs < b.secs
            minus : Timestamp, Timestamp -> Duration
            minus = |a, b| { secs: a.secs - b.secs }
        }
        times : List(Timestamp)
        times = [{ secs: 100 }, { secs: 200 }, { secs: 300 }, { secs: 400 }]
        search(times, Timestamp.{ secs: 300 }) == 2
    }
}

Two gotchas I ran into while writing this:

  • It has to be x.minus(lo), not x - lo. The - operator always returns the left operand's type, so it can't turn two Timestamps into a Duration.
  • A where alias can only constrain its own receiver, so a.Interpolatable(d) : where [..., d.to_f64 : d -> F64] is rejected. That's why the constraints are written out inline.

For List(Str): Roc strings don't support < (there's no is_lt), so a string version can't go through Comparable. You'd need a separate search_str, or a variant that also takes the comparison as a function (like your binary_search takes pred), and compare the to_utf8() bytes yourself.

Aurélien Geron (Nov 08 2026 at 23:43):

Python's official philosophy on this point is "There should be one-- and preferably only one --obvious way to do it." It's only about obvious ways to do it. Plus, it's not strict: it's just a preference.

Ruby is a fun language, and its do-it-your-way philosophy is great when you're working on a personal project or when you need a DSL, but in my experience it doesn't scale well in large projects, at least in the Ruby projects I worked on: my colleagues were having way too much fun defining layers upon layers of "cool" abstractions and DSLs that were only used in one place. And this go-wild philosophy also extended to the ecosystem, where packages had new breaking changes every other day. More freedom is great when it doesn't translate to messy and unstable code. We didn't have this issue with Python projects.
