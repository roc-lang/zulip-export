Richard Feldman (Sep 27 2026 at 04:28):

one relatively quick way I think we could improve this: we could make structural tag unions automatically get a method called (let's say) rewrap which would essentially do the relevant part of this match for you, and then Try could get a rewrap_ok and rewrap_err which would delegate - so then you could replace that whole match with:

Function(fn) => Ok((fn(args).rewrap_err()?, env))

Richard Feldman (Sep 27 2026 at 04:29):

there are other things we could try to do to make that method call unnecessary, but that whole subject is a big can of worms that I don't think should be in scope for 0.1.0, whereas an auto-generated method called rewrap (or some other name if we can think of one) on tag unions, plus Try.rewrap_ok and Try.rewrap_err which delegates to it, could at least make this situation nicer

Richard Feldman (Sep 27 2026 at 04:30):

Aurélien Geron (Sep 27 2026 at 10:27):

I think you can, the following works fine, I just tested it:

f : U64 -> Try(U64, [TooBig, ..])
f = |x| {
    if x > 1000 { Err(TooBig) } else { Ok(x) }
}

g : U64 -> Try(U64, [TooBig, TooSmall])
g = |x| {
    if x < 100 { Err(TooSmall) } else { f(x) }
}

main! = |_| {
    res = g(2000)
    dbg res
    Ok({})
}

Aurélien Geron (Sep 27 2026 at 10:29):

This also works:

main! = |_| {
    color : [Red, Blue, ..]
    color = Red

    more_colors : [Red, Green, Blue]
    more_colors = color

    dbg more_colors
    Ok({})
}

Aurélien Geron (Sep 27 2026 at 10:32):

It also works if you make more_colors open: more_colors : [Red, Green, Blue, ..].

However, it will not work if colors is closed, regardless of whether more_colors is open or closed. This is the case where Richard's unwrap (or widen) would be useful:

main! = |_| {
    color : [Red, Blue]
    color = Red

    more_colors : [Red, Green, Blue]
    more_colors = color.widen()

    dbg more_colors
    Ok({})
}

Aurélien Geron (Sep 27 2026 at 10:55):

My understanding is that you can't use open unions (..) in nominal types unless you use a type parameter for the extra errors (..errs). I'm not sure why. I'm guessing it's because eventually the compiler needs to decide on a particular list of possible tags for the union, and it needs to be the same list for all the functions in your recursive structure.
