Richard Feldman (Aug 18 2026 at 22:06):

but in general the way it works is:

  • downloaded packages stay in there indefinitely, and roc looks in there before attempting to use the Internet, so if you can copy a downloaded package in there from somewhere else, that should address the firewall issue for now (I hear you that it's not a great UX right now!)
  • old build artifacts (based on date of last use) get automatically cleaned up during roc builds, so you shouldn't need to clean them manually

Richard Feldman (Aug 18 2026 at 22:10):

the design goals here are:

  • there's nothing to add to .gitignore - projects don't make a mess in your local dir, which is valuable for the scripting use case if you want to have dependencies
  • all builds automatically share everything, including not just downloaded packages but also intermediate build artifacts - so that means if you have multiple checkouts of the same project, or which share a bunch of code, they will all automatically share relevant build artifacts behind the scenes and you won't be paying for redundant copies of packages or build artifacts (just the source code itself)
  • roc cleans up after itself when it comes to build artifacts, so you don't need to "periodically clean things" to prevent your disk from filling up
  • packages stay downloaded indefinitely, on the theory that build artifacts can be regenerated from source code + packages, but packages can't, so deleting them automatically would mean you could no longer build without being able to re-download, which would be bad. Also, cached packages only grow when you add a new one, as opposed to on every single build, so their growth trajectory is less much lower than cached build artifacts

Another aspect to this is you only need to make a network request if you don't already have packages in your cache... because packages are content-hashed we can know for certain if you have the exact files locally and there is never any need to check.
