Run the dotnet glue (after porting):

roc glue glue/DotNetGlue.roc host/ platform/main.roc

dotnet build host/myproject.sln

roc build app/main.roc

arg 1) path to glue generator
(fork one of the above as a template, or give file to LLM & command it to port to dotnet)

arg 2) destination for generated .net glue

arg 3) the platform that is being used as inputs for the glue

Scott Campbell (Oct 08 2026 at 06:21):

And as for a dotnet platform itself, luke has made some roc-platform-template-{lang} templates that you can reference, with some basic-cli-like effects; stdout etc.

https://github.com/lukewilliamboswell?tab=repositories&q=platform-template&type=&language=&sort=

The {lang} host in the src/ directory produces a libhost.a (archive file, which contains a libhost.o object file) for the platform/main.roc targets:

    targets: {
        inputs_dir: "targets/",
        x64mac: { inputs: ["libhost.a", app] },
        arm64mac: { inputs: ["libhost.a", app] },
        x64musl: { inputs: ["crt1.o", "libhost.a", app, "libc.a", "libzigc.a", "libcompiler_rt.a"] },
        x64v1musl: { inputs: ["crt1.o", "libhost.a", app, "libc.a", "libzigc.a", "libcompiler_rt.a"] },
        arm64musl: { inputs: ["crt1.o", "libhost.a", app, "libc.a", "libzigc.a", "libcompiler_rt.a"] },
        arm64v1musl: { inputs: ["crt1.o", "libhost.a", app, "libc.a", "libzigc.a", "libcompiler_rt.a"] },
        x64win: { inputs: ["host.lib", app] },
    }

So you'll need to configure dotnet to produce an object or archive file; ie libhost.a that roc (or any other linker) can consume (depending on the target arch-OS).

The rest is sorting out any remaining linker errors, mismatching symbols etc. objdump can be useful to inspect the files.

You'll need to supply any other archive or object files that you may have dependencies for... libc.a if needed, crt1.o if producing an executable... etc.

Implement & export some memory allocation functions and allocate & initialize some memory for the roc host to reside in memory (whatever is suitable for your specific platform's requirements).

And then expanding the scope with your platform's requirements.
