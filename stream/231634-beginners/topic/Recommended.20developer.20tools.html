I'd like to update the Install section of the website to provide some info on developer tools for Roc. What do you recommend?

Editor extension

I'm aware of:

  • Zed:
    • The Roc extension for Zed by @Alf Richter.
  • VSCode
    • The Unofficial Roc extension for VSCode by @Ivan Demchenko.
    • koliyo/vscode-roc by @Nils Hjelte, a port from Alf's Zed extension.
    • Hasnep/roc-vscode by @Hannes, also a port from Alf's Zed extension.
    • lukewilliamboswell/roc-vscode-unofficial by @Luke Boswell, a fork of Ivan's extension.
    • v4rm4n/roc-vscode by @Adityavarman Manjunath, which is a thin wrapper around roc experimental-lsp, so it keeps up with nightlies.

Did I miss any? Which of these are actively maintained? In a recent conversation (#contributing > roc-vscode-unofficial), Ivan said he was looking for volunteers to take over his repo, and @Will Hawkins kindly offered to help. I'm not sure what the status is.

Are there any other editor extensions that you like using with Roc?

Other tools

  • Roc comes with package management, formatter, testing framework, documentation generation, but does anyone use any other tool on top of these? Such as a mocking library for example?
  • Are there any linters?
  • Any coverage tools?
  • Would you recommend any bundlers?

My goal is not necessarily to list every possible tool, but to help the users get up and running and productive quickly.

Aurélien Geron (Oct 29 2026 at 18:50):

Yeah, I used one a very long time ago. The process went something like this:

  • gather all the necessary files
  • configure application metadata (app name, version, default install path...)
  • define where everything goes
  • customize the wizard interface (e.g., enable license agreement, select components...)
  • add branding
  • configure the uninstaller
  • compile and test

Most of this doesn't really affect Roc itself, except perhaps the very first step: it would be nice to have a command to fetch all dependencies. I've already run into this with Exercism: their test runner runs in a container with no internet access, so the image must contain every single package and platform that the exercises need. Currently, the Dockerfile installs Roc, then it runs a small Roc app that imports all the necessary packages, then it also runs a Roc program for each possible platform. This pulls all these dependencies into the Roc cache so it's part of the Docker image. It would be nice to be able to just run roc download-dependencies <path> and let it download every single dependency in the Roc files within that path, as well as their own dependencies.

Such a command would also help with an installer creator: the machine we're installing to may have restricted internet access, so it's good to have the installer contain every single dependency.
