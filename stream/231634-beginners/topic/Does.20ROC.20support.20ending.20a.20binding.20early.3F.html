Luke Boswell (Nov 25 2026 at 02:45):

Roc is memory safe, and uses automatic reference counting under the hood; it's not possible to accidentally use after free etc. If you find anything that is use after free, that is a compiler bug

Luke Boswell (Nov 25 2026 at 02:46):

If you modify something that has multiple references to it, Roc will clone the value and give you another copy.

Luke Boswell (Nov 25 2026 at 02:47):

So roc is semantically immutable -- any in-place mutation optimisation is automatic.

Luke Boswell (Nov 25 2026 at 03:42):

There isn't a way to do that in Roc syntax.

But there are tools floating around which can help you.

My favourite is to write tests using roc-fuzz and use the builtin allocation measurements to help me do that. I can write a test that says "guarantee this function makes no allocations" and then if it fails I know I have violated that by leaving a stray reference around.
