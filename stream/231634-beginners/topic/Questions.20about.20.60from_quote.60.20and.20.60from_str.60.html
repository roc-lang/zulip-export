Topic: Questions about `from_quote` and `from_str`

Aurélien Geron (Sep 25 2026 at 05:29):

My understanding is that from_quote is always executed at compile time, and if it compiles successfully, we can entirely ignore the error case. Is that correct?

If so, are the following basically equivalent (they don't call the same function but they do the same thing)?

d: Date
d = "2018"  # actually calls Date.from_quote("2018")

Ok(d) = Date.from_str("2018")

Why do we need both from_quote and from_str? Couldn't we get away with a single function?

Also, why must from_quote return Try(_, [BadQuotedBytes(Str)])? Couldn't it allow any other error?

For context, there's an Exercism exercise where the tests look like this:

expect {
    result = shared_birthday(["1966-07-29", "1977-02-12", "2001-12-25", "1980-11-10"])
    result == Ok(Bool.False)
}

The function must simply parse the strings and return True if any two dates share the same day & month. The type spec of the shared_birthday function could be:

shared_birthday : List(Str) -> Try(Bool, _)

The user would have to implement this function and take care of parsing the dates (returning an error in case of a parsing error).

But it might be more instructive and more idiomatic to define it as:

Date :: {year: I64, month: U8, day: U8}.{
    from_quote : Str -> Try(Date, [BadQuotedBytes(Str)])
    ...
}

shared_birthday : List(Date) -> Bool

In this case the test above would look like this instead:

expect {
    shared_birthday(["1966-07-29", "1977-02-12", "2001-12-25", "1980-11-10"])
}

Wdyt?
