Anton (Nov 16 2026 at 19:10):

How can I check if my implementation does:

From Opus 5.5:

The practical check is a stress test: call the function with an input big enough to make it recurse millions of times.

1. Stress test with expect

sum_tail : U64, U64 -> U64
sum_tail = |n, acc| if n == 0 acc else sum_tail(n - 1, acc + n)

expect sum_tail(10_000_000, 0) == 50_000_005_000_000

Run it with roc test MyFile.roc --no-cache. I tried this with your local roc-main build:

  • sum_tail (tail call): the test passed in about 0.35 s.
  • n + sum_plain(n - 1) (not a tail call): at the same depth it fails with:
    This Roc program overflowed its stack memory. This usually means there is very deep or infinite recursion somewhere in the code.

If your function survives a depth in the millions, it qualifies. This test doesn't tell you which optimization kicked in, but that rarely matters: each one means the stack doesn't grow.

2. What makes a call qualify

From the "Tail Calls" section of docs/langref/functions.md and the compiler code (src/lir/tail_call_builder.zig), the recursive call's result has to be returned exactly as it is.

These still qualify:

  • The call sits at the end of an if or match branch.
  • You bind the result to a name and return that name.
  • An early return f(x).

These don't qualify:

  • Doing anything with the result after the call: n + f(x), f(x)?, Ok(f(x)), calling a function on it, and so on.
  • The usual fix is to pass an accumulator along as an extra argument, like sum_tail above.

Exception, "modulo cons": if the function returns a recursive tag union and the call's result goes straight into one of its tags, it also becomes a loop. For example, Cons(x, count_up(n + 1, end)) where the return type is LinkedList(a).

Calls to other functions: a tail call to a different function, or to a function passed in as an argument, reuses the current stack frame. So mutually recursive functions like is_even/is_odd that only call each other in tail position can't overflow either.

3. Compiler debug flag

roc can be built with a debug option that logs this:

zig build roc -Dprint-trmc=true            # one line per transformed function on stderr
zig build roc -Dprint-ir-after-trmc=true   # full IR dump of each transformed function

The output looks like tce: proc p12 (0 construct sites, 1 tail calls). It identifies functions by internal number, not by name, so it's most useful on a small file with a single recursive function. I haven't tried these flags; the stress test is simpler.

Vanand Gasparyan (Nov 21 2026 at 16:12):

That was quite helpful @Anton . I ran some experiments and found a version of the implementation that enables TCO. Here it is:

partition_point : List(a), (a -> Bool) -> U64
partition_point = |list, predicate| {
  partition_point_helper : List(a), (a -> Bool), U64 -> U64
  partition_point_helper = |lst, pred, offset| {
    if lst.is_empty() {
      return offset
    }
    mid_idx = lst.len() / 2
    mid = list_get_unsafe(lst, mid_idx)
    if predicate(mid) {
      partition_point_helper(lst.drop_first(mid_idx + 1), pred, offset + mid_idx + 1)
    } else {
      partition_point_helper(lst.take_first(mid_idx), pred, offset)
    }
  }

  partition_point_helper(list, predicate, 0)
}
