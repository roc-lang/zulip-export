Aurélien Geron (Oct 13 2026 at 04:31):

Yeah, it's this sentence "This is heavily WIP!" that made me think we need to complete/update the docs before 0.1.0. If the langref is already done, great! :grinning_face_with_smiling_eyes:

I ran into a number of outdated statements here and there, such as saying that an if must always have an else, even though this is no longer true since we have return now.

The playground is also outdated, I'm not sure why (I thought we had fixed that).

The examples page feels disorganized. It should perhaps be organized by categories, and/or examples should perhaps have tags about their main concepts or main API.

Things feel a bit disjointed: perhaps the langref and standard lib docs should point to examples, and vice versa.

Also, several things are not covered by examples, if I'm not mistaken:

  • Iterators and ranges
  • for, while, and var versus fold
  • Nominal versus opaque types
  • Polymorphism and where constraints
  • Closures
  • Custom equality and hashing
  • Sets

Moreover, having some examples of common packages and platforms would be good, such as unicode (in more depth), path, roc-ray, etc. Alternatively we could just point to these packages, but right now we have examples for basic-cli, basic-webserver, http, roc-ascii, roc-parser, and roc-random, so I think it would make sense. The platform and package examples should each be in their own section in the examples page.

Perhaps a "Tips and tricks" or "Best practices" page would be useful, and a docathon would help figure out what to recommend. For example I like to use Try(Foo, _) during dev and be more specific only at the end, switching to Try(Foo, [A, B, C]).

There's certainly more to do. Completing this To-Do list is what I suggested for step 1. Perhaps there's not enough work to justify step 2, but in many projects I've worked on, the docs weren't get enough love, and I've found that a short focused effort is a good solution to solve that.

Aurélien Geron (Oct 15 2026 at 10:24):

I also submitted PR #310 with 26 new examples covering more Roc language features, packages, and platforms:

Types and functions

  • NominalTypes — nominal and opaque types.
  • NestedTypes — types defined inside other types.
  • OpenRecords — accepting records with additional fields.
  • PatternAliases — naming an entire matched pattern.
  • Closures — capturing values in functions.
  • Boxes — using Box.
  • RecursiveTypes — recursive and mutually recursive types.
  • MutualRecursion — mutually recursive functions and tail calls.
  • Polymorphism — where constraints and reusable aliases.
  • DerivedMap — deriving map and map!.
  • CustomEquality — custom equality and hashing.
  • CustomOperators — arithmetic, comparison, and range operators.

Collections and iteration

  • Sets — working with sets.
  • Loops — for, while, var, and fold.
  • Iterators — custom iterators, lazy pipelines, and ranges.
  • Streams — stream pipelines, for!, and custom file-reading streams.

Error handling

  • ExpectTry — using ? inside expect.
  • WrappingArithmetic — handling overflow with wrapping and saturating arithmetic.

Parsing and encoding

  • StringPatterns — capturing filenames and parsing path IDs.
  • AdvancedParsing — optional fields, defaults, and parsing formats.

Organizing and publishing code

  • Documentation — generating documentation with roc docs.
  • PackageAuthoring — creating and bundling a package.
  • PlatformAuthoring — writing C, Zig, and Rust hosts.

Packages

  • Paths — using the path package.
  • Unicode — graphemes, scalars, word boundaries, and casing.

Platforms

  • RocRay — an interactive graphical application.
