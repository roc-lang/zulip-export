Steve Howell (Oct 29 2026 at 11:51):

I'm working on creating a pure-Roc implementation of the chat-centric markdown flavor that I have been using on my personal chat server since about May of this year.

The original implementation was based on a couple community-approved golang packages for parsing and rendering common markdown. I then soon ported it to zig. It's battle-tested with several thousand real-world messages from me and a couple friends using the chat, and it's extensively tested with automated tests for correctness and dealing with pathological inputs.

The chat markdown's design is also influenced my time on the Zulip project as both a developer and user. I actually did significant work on Zulip's markdown parser, which is a heavy layer over python-markdown.

Steve Howell (Oct 29 2026 at 11:57):

There's really no such thing a markdown standard in the chat world. Zulip has had its own flavor of markdown since 2014. Chat has different ergonomics than document creation, plus chat has a large attack surface. So chat-centric markdown implementations usually cut certain features for safety while adding other features for ergonomics or better expressiveness.

For safety, the most obvious thing that markdown authors do is allow-list only a few tags like <img> tags, and of course those tags have restricted attributes. You're not bring down this Zulip server with a simple script tag, nor would you bring down mine.

Steve Howell (Oct 29 2026 at 11:59):

My only audience up until now has been my little chat community, but now that I'm in the Roc world, I intend to support documentation as well. With docs you usually want a mode where you know the markdown source is trusted, and certain features that don't really work for chat (e.g. tables don't work great in chat, because the syntax is so clumsy) are quite important for docs (e.g. tables).

Steve Howell (Nov 06 2026 at 19:04):

A poorly written markdown processor can be exploited for denial-of-service attacks. Even quadratic behavior should be avoided; you can write really naive ones with exponential attacks.
