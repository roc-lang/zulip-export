Zak Kohler (Oct 13 2026 at 19:53):

This is claude's summary for porting our Roux dragrace site's cli ops:

Thanks for asking! I checked our tooling (a ~10k-line Go ops tool we want to port to Roc) against 0.26.0-rc2, and it covers nearly everything. Our asks, in priority order:

  1. Catching SIGINT/SIGTERM. For example Signal.catch!([Interrupt, Terminate]) plus a way to poll for pending signals, with blocking waits (Duration.sleep!, Child.read!, Tcp reads with a timeout) returning Err(Interrupted). Today Ctrl-C or systemctl stop kills the process before it can clean up; for us that means cloud VMs left running and billing. No issue exists yet, and I'm happy to file one. (Notes: it would have to work alongside the Tty handlers in src/tty.rs, and sleep! currently restarts after a signal.)
  2. Unix socket connect (+1 #500): UnixSocket.connect!(path, ...) with the same API as Tcp.Connection. listen! would be a bonus.
  3. File permissions: a mode on create (e.g. open_writer! with { mode: 0o600 }, so secrets are never world-readable) and a chmod (Path.set_permissions!).
  4. Symlinks: Path.symlink!(target, link) and Path.read_link!(path).
  5. Http redirects: document that Http.send! doesn't follow them (GitHub release downloads always 302, and Http.get! then fails as a JSON error). Maybe an opt-in max_redirects.
  6. (minor) A StdoutMode that sends the child's stdout to the parent's stderr, the mirror of MergeWithStdout.

Only #1 has no workaround from inside the program. The others are conveniences we can shell out around.

That seems good. The goal is to avoid reusing the exec name with a different behavior from C function or the shell command. By the way, I recommend adding an actual exec! function, which replaces the current process with the new executable, just like as C function or the shell command does it. It can be a useful tool for scripting in Roc.

notramo (Oct 14 2026 at 10:53):

Windows has Unix socket support, but it's somewhat limited (e.g. no datagram, no file descriptor passing). However, even a common subset would be very useful. I.e. connect to a stream socket and write data into it. It's the most common use case for sockets.
