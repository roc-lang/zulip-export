In your example: pub const ProcessResult = if (@sizeOf(usize) == 4) extern struct {
, in both cases, the tag is the same tag: ProcessResultTag,... It's only the payload that's different.

Matching example:

const tag : abi.HostRegister_classResultTag = .abi.HostRegister_classResultTag.Ok;

const r = switch (tag) {
    .abi.HostRegister_classResultTag.Ok => {
        "It's Ok tag";
    },
    .abi.HostRegister_classResultTag.Err => {
        "It's Err tag";
    },
};

return r;

And in my case, I have two error types, so there is top level Err tag, with a payload with another ErrTypeDiscriminator tag inside it:

/// Tag discriminant for NameLengthErrOrOutOfMemoryClassErr.
pub const NameLengthErrOrOutOfMemoryClassErrTag = enum(u8) {
    @"NameLengthErr" = 0,
    @"OutOfMemoryClassErr" = 1,
};

/// Payload union for NameLengthErrOrOutOfMemoryClassErr.
pub const NameLengthErrOrOutOfMemoryClassErrPayload = extern union {
        @"name_length_err": RocStr,
        @"out_of_memory_class_err": RocStr,
};

Two constructor function examples:

fn registerClassResultOk(class_id: u32) abi.HostRegister_classResult {
    if (comptime @sizeOf(usize) == 4) {
        var result: abi.HostRegister_classResult = undefined;
        result.tag = .Ok;
        const p: *u32 = @ptrCast(@alignCast(&result.payload));
        p.* = class_id;
        // clear any leftover bytes beyond the u32 if you care
        return result;
    } else {
        return .{
            .payload = .{ .ok = class_id },
            .tag = .Ok,
        };
    }
}

fn registerClassResultErr(
    err_tag: abi.NameLengthErrOrOutOfMemoryClassErrTag,
    msg: abi.RocStr,
) abi.HostRegister_classResult {
    if (comptime @sizeOf(usize) == 4) {
        // Build inner error value into its opaque payload
        var err_val: abi.NameLengthErrOrOutOfMemoryClassErr = undefined;
        err_val.tag = err_tag;
        const str_ptr: *abi.RocStr = @ptrCast(@alignCast(&err_val.payload));
        str_ptr.* = msg;

        var result: abi.HostRegister_classResult = undefined;
        result.tag = .Err;
        const err_bytes = std.mem.asBytes(&err_val);
        @memset(&result.payload, 0);
        @memcpy(result.payload[0..err_bytes.len], err_bytes);
        return result;
    } else {
        const err_val: abi.NameLengthErrOrOutOfMemoryClassErr = switch (err_tag) {
            .NameLengthErr => .{
                .payload = .{ .name_length_err = msg },
                .tag = .NameLengthErr,
            },
            .OutOfMemoryClassErr => .{
                .payload = .{ .out_of_memory_class_err = msg },
                .tag = .OutOfMemoryClassErr,
            },
        };
        return .{
            .payload = .{ .err = err_val },
            .tag = .Err,
        };
    }
}

Note: I'm using these function to return zig errors, back to the app as the result for when the zig effect fails.

Payload constructors already exist, it's only if you want to construct an entire Result, there isn't a constructor function for that yet. And an LLM helped me to write my slop constructor functions... so perhaps I could just call the glue payload constructors, and discard the additional logic.

"But I don't want to 'if (comptime @sizeOf(usize) == 4) {' because the ZigGlue.roc could change, and break the payload (or any other part of the) ABI, and if the zig type checker doesn't catch it... because it's an opaque type or something..."

(One could use the glue generated payload constructors abi.HostRegister_classResult.payload_ok(1234), where the if (@sizeOf(usize) == 4) extern struct { logic has already been implemented for you in the generated glue, instead of LLM copy pasting the implementation, or..)

One could vendor or pin a version of ZigGlue.roc, and add additional constructor functions, to enforce that they're both kept the same "at glue generation time".

It's just a matter of preference, "do i want the thinnest possible glue with just ABI types, or a more fully featured glue with constructor helper functions for everything".

I do think that the more beginner friendly approach, could be to include entire Result constructor helper functions in the default upstream glue.

And if you're desperate enough, one could even swap out the default glue platform entirely for something even more custom, like in my case where I have a need to generate something more complex, then just exclusively roc abis and extern stubs, but also export implementations for secondary glue-to-glue functions because I have two C-FFIs to contend with.
