Richard Feldman (Oct 23 2026 at 18:17):

  1. Is there other nondeterministic behaviour in the language (like HashMap iteration order in Rust)?

no, we go way out of our way to make everything as deterministic as possible actually - including across targets, e.g.

  • Dict (our hashmap equivalent) in the sdlib always iterates in the order the keys were inserted, although under the hood it actually does some randomization of internal, private storage (using memory addresses as the seed so it can piggyback off the OS's ASLR instead of needing to do a syscall to get a random seed) to mitigate hash flooding attacks - but we've been careful to make sure this detail is not observable in Roc programs - you'd have to look at the raw bytes in memory (or observe performance characteristics, e.g. because you're attempting a hash flooding attack) to tell we're doing it
  • the compiler never emits any floating-point instructions that behave differently across CPU architectures
  • we don't have usize or any other ways to write Roc code that gives different answers based on what target you're compiling for (see for example #beginners > ✔ OS-specific APIs in platforms) - the only thing that can happen differently on different targets is something crashing on one target but not on another, because it ran out of system resources (e.g. heap OOM, stack overflow, or if you have 64-bit addresses, you can make a List with more than 2^32 items in it, but if you try to do that on a 32-bit target, you'll get a crash when it runs out)

the main reason we do this is actually because of our eager compile-time evaluation - which basically evaluates any expression at compile time if it can be evaluated at compile time (e.g. it doesn't depend on any runtime inputs). This is only safe to do if there is no chance that it would change the runtime behavior of the program, which in turn means (especially in conjunction with caching of compilation artifacts, which is critical to compilation speed) that evaluation on your machine has to give the same answer as evaluating on any other machine would, even if that other machine has a different CPU architecture, or is wasm, etc.

Luke Boswell (Oct 23 2026 at 21:53):

I have a platform that does this already, if you take a look at roc-signals it swaps out the host depending on what your target it. The app runs identically and has no way to know the host is different. If you target the web you get a WASM module for loading into the browser. If you target native you have a test harness which is driven deterministically through scripts written in S-expressions.

Also have a look at roc-gui that has a nicer builtin test harness.

I experimented previously which completely capturing and replaying everything crossing the boundary in roc-ray but I ripped it out because it was overkill for graphics and memory requirements we large with any decent duration of capture... but the idea worked really well.

Re Rust verse Zig I dont think there is too much of a difference, both will be a good choice for your use cass.
