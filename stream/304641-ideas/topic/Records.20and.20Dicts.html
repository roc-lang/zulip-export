Topic: Records and Dicts

Aurélien Geron (Sep 06 2026 at 21:34):

Somewhat of a radical idea this morning, and likely one that has already been discussed and rejected before, but I couldn't find the discussions: since records are basically tuples with named fields, why not use the tuple syntax (with parentheses) for records, which would free up the curly bracket syntax for Dict and Set literals?

For example:

bart = (first_name: "Bart", age: 10)
dict = {"one": 1, "pi": 3.14}
set = {1, 3, 5, 7}

For empty Dict or Set, we could do like Python and assume {} is an empty Dict (since Dict is more frequently used than Set), or we could have some syntax like {:} for an empty Dict.

empty_record = ()
empty_dict = {}
empty_set = Set.empty()

# or

empty_record = ()
empty_dict = {:}
empty_set = {}

Pros:

  • A nice literal syntax for Dict and Set.
  • A more explicit connection between tuples and records.
  • Smoother transition from languages like Javascript, Ruby, Perl, Elixir, Clojure, Dart, and many more.

Cons:

  • Yeah, it's a massive change for users, but maybe one that can be automated via roc fmt? And perhaps the current record syntax could still be supported for a while, I don't think there's any ambiguity, except for {} (unit), which would become ().
