Topic: show dbg only for failed expect

Johannes Maas (Nov 22 2026 at 10:49):

When running roc test, have you considered showing the output of dbg only for expects which failed? I have tried to search Zulip, but haven't found a discussion of this.

I think this is different from inspecting the used values, which I found is currently not available but will come back after v0.1.0: #beginners > How to see values from failing top-level `expect` statements @ 💬

The difference is that I might have some dbg statements in my functions, not inside my test. These clutter the output of roc test making it difficult for me to distinguish which are related to the failing test I want to know more about.

The dbg in the test code I can hide behind an if, so even without the automatic display of used values I can output the relevant values only when the test fails, which cleans up the output of roc test and makes it easier to understand what went wrong.

But I think this is not possible for dbg inside the functions under test, which I might want to do to understand each step inside the function. Here, I think I would need support from roc test to clean up the output.

I think I've seen this behavior of only outputting logs from failed tests in Jest, but I have trouble finding documentation on this, so I'm not sure if I remember that correctly.

I thought I'd share the idea in case this is something that others might find useful as well.

Johannes Maas (Nov 23 2026 at 06:46):

I think there might be use cases for both outputting all and outputting only for failing tests. So there would need to be a config flag, as Aurélien suggested.

One option would be to print all by default and if there are outputs for successful tests to give a hint at the end of the report of which flag to use to only show the failing outputs.

That way in your case you would see the output on the infinite loop by default, but if you are overwhelmed by the outputs it would guide you to how to clean them up.
