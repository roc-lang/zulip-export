Richard Feldman (Sep 28 2026 at 21:25):

some more detail on reference counting that might be helpful:

  • let's say you have 2 threads running
  • on each of those threads you pass the same refcounted Roc value
  • you're responsible for making sure those Roc functions receive accurate refcounts, because Roc doesn't have a stateful runtime; neither of those Roc functions knows the other function exists, or that it's running on a thread in parallel with another thread that's also running a Roc function, etc.
  • in other words, if you gave each of these 2 Roc functions the same value, you need to make sure they each receive it with a refcount of 2
  • if you give each Roc function the same value with a refcount of 1, they'll both thing it's safe to mutate in-place, and you can get really nasty behavior
  • on the other hand, if they each get a refcount of 2, everything should work fine because Roc will automatically do atomic refcounting on them
  • if you get the values back (as in, the Roc functions return them) their reference counts should be accurate again (note: the refcount might be higher than the refcount they had when you passed them in, if any of the other values the Roc functions return are referencing them)

Richard Feldman (Sep 28 2026 at 21:25):

so that's what I mean regarding "you have to keep the reference counts accurate"

Richard Feldman (Sep 28 2026 at 21:26):

compiled Roc functions are, by design, totally stateless - that's one reason why the host has to provide things like alloc and dealloc

Richard Feldman (Sep 28 2026 at 21:26):

you just call them passing values, they operate on those values, call some functions the host itself provides (alloc, dealloc, crash, effectful functions, etc.), and then return, and that's it; there is no stateful runtime to initialize or deinitialize because once those functions return, they're done

Richard Feldman (Sep 28 2026 at 21:27):

if there's any leftover stuff to be cleaned up, it's all stuff the host already knows about (e.g. allocations done using the host's own allocation system)

Richard Feldman (Sep 28 2026 at 21:28):

but that does mean each compiled Roc function call is innately oblivious to what other Roc function calls are running, if any, and makes no attempt to coordinate between them - so the host is responsible for making sure they receive accurate refcounts when they're called, and then doing any necessary cleanup on the return values after they finish
