Topic: Drag Racing Roc Packages

Luke Boswell (Oct 28 2026 at 04:49):

@Zak Kohler made a drag race for his web framework Roux... and talked about it in the last meetup. I just had an idea while looking at roc-awesome and thinking about the growing list of packages in the ecosystem ... I wonder if we could extend the drag race idea, and generalize it somehow to run races for basically every package.

Getting the environment could be a challenge, but I would pick a linux machine running Nix and roc-blueprint, then we can pin the Go/Rust/Python/Javascript tooling.

I don't know if this is a crazy idea... but basically pick the smallest DO droplet or something, and have it continuously updating and running the drag races and reporting that in a website?

I've done a bit of work on all my parsers for example, and things like roc-time or roc-pdf etc... basically I'd love to know how everything compares, and track that over time too.

I've mostly been benchmarking the implementation to help me find obvious bugs and ensure it's efficient. I haven't been aiming to be the fasted or anything. Just doing this alone has caught an enormous amount of correctness bugs.

I imagine it would be beneficial for the community to understand how Roc packages are performing across measures like speed, memory etc. I've had a lot of fun challenging myself with performance goals on various things.

Interested to know what others think about this.
