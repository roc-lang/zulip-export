Topic: LSP showing optimizations

Krzysztof Skowronek (Oct 27 2026 at 21:08):

In C# the LSP (that's a bit more complicated there, but let's say the LSP) can show you things like this:

Object allocations, things escaping scope etc

I think it would be great if the Roc LSP provided a highlight for when the reference count increases above 1, and then another one when it increases further. This would make writing optimized programs much easier.

I've using Roc a bit here and there, mostly for agents skills to replace Python, and sometimes I "race" it against F#, Python and some others, and then ask the agents to optimize the program because I want Roc to win of course. When it gets stuck, I give the compiler repo as context, so it learns about all the in-place mutations options, and that ends up being the biggest factor in real life things.

Probably an LSP indication (or even something weaker than compiler warning, like a diagnostic) that points "this line allocates on heap", "this line makes the ref count 2, so no in place mutation" and would make this much easier, not only for AI.

If it offers a code action fix "refactor for in-place mutation" - that's even better!

is that achievable?

Luke Boswell (Oct 27 2026 at 21:13):

Kind of related ... but for optimizing pure Roc implementations, I like to kill two birds with one stone. I reach for roc-fuzz and write lots of small property based fuzz targets, and include memory invariants I want to hold too. This has the benefit of flushing out unnecessary clones, scaling issues, and also catches correctness bugs all in one swoop.
