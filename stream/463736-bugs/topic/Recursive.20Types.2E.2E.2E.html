import cli.Stdout

# lazy CIS stream type definition...

# show the expanded CIS Stream for given `n` elements...

showCISFor = |cis, n| {
  loopi = |icis, i, lst| {
    if (i <= 0) { Str.join_with(List.map(lst, |e| e.to_str()), ", ") }

module Main exposing (main)

import Html exposing (Html, text)

-- recursive stream type...
type CIS a = CIS a (() -> CIS a)

cisStringTo : Int -> CIS Int -> String
cisStringTo n cis =
  let
    loop i (CIS hd tlf) lst =
      if i <= 0 then
        String.join ", "
          <| List.map String.fromInt
          <| List.reverse lst
        else loop (i - 1) (tlf()) (hd :: lst)
  in loop n cis []

-- generate stream of two and all odds following...
cisTest : () -> CIS Int
cisTest () =
  let next i = CIS i <| \() -> next (i + 2)
  in CIS 2 <| \() -> next 3

main : Html Never
main = cisTest () |> cisStringTo 20 |> text

Yes—I ran it successfully with nightly-2026-11-12-ce942d6, the latest published nightly at the time of testing (13 November 2026).

Your CIS declaration is nominal. The problem is inference inside the local recursive functions: bare Cons allows an anonymous structural type to form. Using CIS.Cons explicitly in both construction and pattern matching resolves it. This distinction is described under qualified tags.

Here is the working program:

app [main!] {
    cli: platform "https://github.com/roc-lang/basic-cli/releases/download/0.28.0/2yhxoR7cZPSYbyUzPWULFw8AA6QEcdsgFNRmzu7pZbst.tar.zst",
}

import cli.Stdout

CIS(a) := [Cons(a, {} -> CIS(a))]

showCISFor : CIS(a), I32 -> Str where [a.to_str : a -> Str]
showCISFor = |cis, n| {
    loopi = |icis, i, lst| {
        if i <= 0 {
            Str.join_with(List.map(lst, |e| e.to_str()), ", ")
        } else match icis {
            CIS.Cons(hd, tlf) =>
                loopi(tlf({}), i - 1, List.append(lst, hd))
        }
    }
    loopi(cis, n, [])
}

cisTest : {} -> CIS(I32)
cisTest = |{}| {
    next = |i| CIS.Cons(i, |{}| next(i + 2))
    CIS.Cons(2.I32, |{}| next(3))
}

main! = |_| {
    cisTest({}) |> showCISFor(20) |> Stdout.line!()
}

Jared Ramirez (Nov 13 2026 at 03:07):

i don’t think a bug! the inner fn loopi defines Cons as a anon tag union, and nothing before it generalizes gives the compiler information that the Cons is part of CIS. the correct fix here is the qualified tag or an explicit annotation of loopi

this is a known limitation of coercing anon tag unions into nominals (that it is not always possible to do without explicit types like an anno or qualifies ref)
