Topic: excessive copying when annotations are missing

Steve Howell (Nov 24 2026 at 15:14):

Claude found a performance bug during real work on roc-chat.

If a function has no type annotation and returns a record with one list field appended to, Roc copies the whole list on every call. Building 16,384 items takes 11 to 14 seconds; adding the type annotation brings it down to 16 ms.

Probe :: [].{
        push = |{ tag, items }, x| { tag, items: items.append(x) }
        build : U64 -> U64
        build = |n| {
                var $r = { tag: "plans", items: [] }
                for _ in List.from_iter(U64.until(0, n)) {
                        $r = Probe.push($r, "Hello")
                }
                $r.items.len()
        }
        built : U64
        built = Probe.build(16384)
}

Run it with roc check Probe.roc. Annotating push : { tag : Str, items : List(Str) }, Str -> { tag : Str, items : List(Str) } makes it fast.

Steve Howell (Nov 24 2026 at 15:18):

Correction: for this file, building 16,384 items takes about 1.9 s without the annotation and 18 ms with it (8,192 items take 0.34 s, so the cost grows faster than linearly). Run it with roc check --no-cache Probe.roc, since a cached rerun skips the evaluation.

Steve Howell (Nov 24 2026 at 22:05):

quick answer from Claude:

Thanks, Richard. Measured in built programs (the count from argv, so no compile-time evaluation): the unannotated #13468 shape is quadratic under --opt=dev (1.0 s / 4.5 s at 16k / 32k items) and gone with --specialize=yes (8 / 19 ms) or --opt=speed (2 / 3 ms), so you're right that it's the boxy lowering, though it looks like a full list copy per call rather than a flat dispatch cost. #13469's shape is linear in every built mode (dev 12 / 25 ms), so that one copies only in roc check's compile-time evaluation. Also, roc check doesn't take --specialize. It accepts the flag and ignores it.

We use roc check pretty frequently, so I think we still have the pitfall that roc check is gonna be slow for test code. Both of these were found for test code that tests boundary conditions at 64k thingies (a limit in the chat program).
