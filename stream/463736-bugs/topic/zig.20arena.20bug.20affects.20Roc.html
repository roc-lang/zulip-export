Topic: zig arena bug affects Roc

Steve Howell (Oct 26 2026 at 14:46):

See #show and tell > roc on a unikernel (venting about LLM policies) for a little more context, but the executive summary is that zig 0.17 has a double-allocation bug that can plausibly bloat Roc programs.

Here's a tiny Roc app:

app [make] { pf: platform "./platform/main.roc" }

make : U64 -> List(U8)
make = |n| {
        small = List.repeat(1, 100)
        big = List.repeat(2, n)
        big.concat(small)
}

The host's roc_alloc allocates from an ArenaAllocator, and I log what the arena asks of its own allocator. For make(1_000_000), Roc asks for 3,000,164 bytes in all:

stock Zig 0.17.0: arena node grows 1,500,120 -> 5,000,296; arena holds 5,000,272
patched 0.17.0: arena node grows 1,500,120 -> 3,500,152; arena holds 3,500,128

https://github.com/showell/patched-zig-compiler/commit/b2d40f4eff542f5a19c88107cb05b1b5872e57a4 is the fix. I'm not submitting upstream to zig for reasons that I mention on the other topic.
