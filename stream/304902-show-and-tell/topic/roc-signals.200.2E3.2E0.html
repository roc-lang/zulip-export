Luke Boswell (Nov 09 2026 at 02:24):

It's been quite a while since I've been able to announce anything about roc-signals ... but I've given it some love this last week and now we have a new release.

https://github.com/lukewilliamboswell/roc-signals

It's still experimental in many ways, I just completely overhauled the reactive engine to make it faster and also it is now mostly pure Roc with a thinner Zig host. My goal was to match SolidJS on the js benchmarks to establish a performance baseline and ensure this scales effectively... now we have that the next phase is to polish the API and make it nicer to use. It's ok for an Agent to write and build things with now, but I haven't given the API much love and polished it yet with all the nice things Roc has to offer.

If you're interested in the signals based UI then you might find this approach interesting.

I'd love any ideas or assistance with this. I've got a few things on my list to build with roc-signals, so I'll be updating and refining the API as I go.

blu (Nov 12 2026 at 14:33):

Also, interesting note from the agent about how svelte doesn't have the "if statement" downside due to the Svelte compiler turning them into the reactive pieces for you:

Why Svelte doesn't have the article's downside: the article admits signals make you write ifs and loops in a special reactive way (dyn_container, dyn_stack) in Rust. Svelte has a compiler, so you write normal-looking {#if} and {#each} blocks and it turns them into the reactive pieces for you. The article says Rust frameworks mostly lack that option.
