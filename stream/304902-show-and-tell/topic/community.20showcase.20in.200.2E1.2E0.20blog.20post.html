ofekd (Nov 16 2026 at 23:04):

If you'd like, mention Bliss Writer as well

https://blisswriter.app

Bliss is screenwriting software -- a word processor with special rules for screenplays. It is a TUI with the following parts:

  • Rust for terminal communication and other I/O using crossterm, ratatui and other crates
  • Rust for CRDT, using Loro
  • Roc code for screenplay layout and pagination
  • Roc app core (MVU)

Roc's colored purity is great. It allows to draw clear boundaries with less self discipline than any other language I tried.

The performance is very useful here, with every keystroke doing layout and pagination for subsequent pages. Currently my machine types at around 150-200fps for a long script, with scrolling at around 800fps. (These numbers exclude the terminal itself, it's just app performance). You can try yourself by clicking CTRL+SHIFT+ALT+0 in Bliss to show an FPS monitor.

zhen (Nov 17 2026 at 22:06):

https://github.com/zhenweigc/birbGBA
Inspired by FameBoy(GB emulator written in F#), so I decided to make a GBA emulator in Roc.
Still very WIP, as there is no sound, and the emulator throws explicit Err and force quit upon lots of UB documented in ARM7 ISA and Nintendo official manual.
However, after some arch optimization and 4 months of work, it does passes most of test ROMs from GBA-Tests, and can run some basic GBA games at full speed(until it got hit by an opcode with UB)

This project relies heavily on Luke's Roc-Ray to render graphics, will probably rely on it to support sound.


To run it, just build it(against window.roc, runner is headless and is used for early testing), put a BIOS(you can use Emi Huang's emibios/nintendo official BIOS, should all work) and a gamerom under the same folder. Name them to be bios.bin & game.gba

yeah right the frontend UI is just crappy and baremetal, as I do not have much experience in that, and I am a bit lazy :P will add some basic UIs for rom & bios selections later.

And I did use mature project such as NanoBoyAdvance & mGBA as references. Oh, and LLMs are used to Nudge me when I got lost. And during optimiation it helps me to find what drags the game slow.

Karl (Nov 18 2026 at 17:42):

roc-regex is a regular expression matching engine. It's generally competitive performance-wise with other state of the art implementations, including Rust's regex crate on machines with 128-bit wide SIMD.

roc-markdown is a CommonMark + GFM compliant markdown parser.

trantor is an extensible platform system that's designed to build a set of Rust crates into a single platform which was developed in support of...

Kite, which is a native GUI platform and my main effort in Roc. It's from scratch from the shaders up with Clay as a starting point (immediate mode) and for LoC it's around 170k Rust and 50k Roc not including whitespace and comment lines. It's my take on web programming without the browser so the programming model is basically Elm and the styling is basically Tailwind. A majority of the browser's styling capabilities are implemented (gradients, shadows, text decorations, borders, images, grid and flexbox). Most of the demos are flat because it's easy and that's the current trend but the platform has the full set of capabiliites:

There's an animation system with support for element entry/exit transitions, forward/reverse animation chaining, closed-form spring animation, and auto-filmstrip repeated animations so the full app render doesn't happen on every cursor blink. There's a widget system including a data grid and rich text editing.






Since it's built on web concepts, I have an alternate roc platform for running on the DOM that translates the platform calls to the web equivalent instead of the native stack. I've only done simpler demos on it as a proof of concept but it drops the wasm bundle from 9MB (full app in WASM rendering in a WebGL context) to ~300k (DOM nodes+CSS) for the counter demo.

Finally, I have it built for android and running on my e-ink tablet. Many of the resource consumption and styling decisions were made to facilitate apps running well on the device. It doesn't screenshot that well but a non-JVM app with custom e-ink waveform support allows 30ms interaction latency in the PDF reader app instead of the hundreds the vendor app takes.

Proprietary

Real estate agency platform (in production, public-facing)
Runs a huge chunk of BOSTHLM, a Stockholm real estate agency: website bosthlm.se (full-stack Roc/Joy), an internal portal for the realtors with file uploads and a video pipeline built on ffmpeg, a backend for their iOS app, and 35 background jobs that handle syncing listing data, integrations with listing platforms (think Zillow), Facebook/Instagram ads automation, YouTube uploads, email and push notifications etc. Sign in using Passkey, email login using roc-sendgrid. Error reporting using roc-sentry.

The frontend is Joy and the server runs on basic-webserver and roc-pg. Lots of tests using roc-spec and roc-playwright. Generation of marketing material like Flyer for record sales using roc-pdf and roc-qr-code.
At least 203k LOC (not sure exactly)

Business and billing system (in production, internal, not public)
Invoices as PDFs from roc-pdf, emailed through roc-sendgrid, with ZIP archives from roc-zip. Built on Joy and basic-webserver.
139k LOC

Sales system (in production, internal, not public)
A dialer, prospecting and CRM features. Reports using roc-xlsx. Built on Joy and basic-webserver.
122k LOC

Document management system (in production, internal, not public)
Built on Joy and basic-webserver.
54k LOC

Joy

Joy (guide)
Full-stack web apps in Roc, powering several production apps today. Write an Elm-like front-end and share views with the back-end. Server-side rendering, hydration, and communication over typed API's. Compiles to WebAssembly on the front-end and a native binary on the back-end. Check out the Joy guide to try it in your browser! Or Roc and Joy: Productivity in Production to see it in action :)
6.6k LOC Roc, 3.8k LOC Rust, 3.4k LOC JavaScript

roc-pg

roc-pg (video)
A PostgreSQL client which checks your types, schema, and SQL syntax at compile-time! It understands SQL and your database just like Postgres because we ported their parser. It's really fast because it checks your schema against a file, instead of connecting to your database. Check out the video to see what it can do!
40k LOC (mostly the Postgres grammar)
