Topic: Roc package template

Aurélien Geron (Oct 09 2026 at 05:21):

Hi everyone,

I put together a template for pure Roc packages:

https://github.com/ageron/roc-package-template

It sets up a standard directory structure, basic module exports, tests, and CI/release workflows out of the box so you don’t have to wire up boilerplate every time you want to build a new package. You may also find it useful for your existing packages, to get extra workflows and tools.

Hope it saves people some time! Feedback and PRs are very welcome.

Aurélien Geron (Oct 09 2026 at 05:30):

This repo reuses components from various other packages: roc-lang/unicode, roc-lang/http, imclerran/roc-isodate, lukewilliamboswell/roc-parser, and kili-ilo/roc-random.

notramo (Oct 09 2026 at 09:47):

Why not put the Roc files in src/ just like any other language? It's shorter to type for CLI users, and its also in muscle memory for developers who use other languages too.

Aurélien Geron (Oct 09 2026 at 10:06):

Good question, I just followed the existing convention. I'm not sure what the original rationale was. It's package for packages, platform for platforms. For platforms, since there are two languages (Roc + host language), maybe it helps to separate out the Roc code in the platform directory, the host code in src? It might allow the Rust/Zig build tools to work out of the box without tweaks. For pure Roc packages, perhaps src would work just as well. But maybe you can have a project containing a platform and a pure Roc package? I'm not sure...

Luke Boswell (Oct 09 2026 at 10:32):

Karakatiza (Oct 09 2026 at 10:33):

Host code in src/ makes sense as a contrast to platform/

Karakatiza (Oct 09 2026 at 10:42):

The alternative would be to keep src/ for either Roc package code or platform host code, and keep platform/ for Roc glue. The upside is Roc does not "yield" src/ to other languages, the downside is you don't know whether src/ contains code in Roc or some other language without knowing whether you look at a platform or a package. This downside is arguably not that significant.
