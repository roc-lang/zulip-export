Yeah, I didn't intend to upstream it (unlikely to be interest, but who knows). I just wanted to see what was possible to do. And yeah, this might be an example of how to lower from LIR to implement other possible backends.

And yes, regarding the platform/app abstraction:

A Roc platform (as you may know) is two halves: a Roc module (main.roc) that declares the app's entrypoints and the effects it may call ("hosted functions"), and a native host that implements those effects. I reused the compiler's half unchanged and replaced the host half with Lua.

Compiler side. roc build --target=luajit lowers the program exactly as the interpreter build does, down to ARC-complete LIR. The LIR already marks the platform boundary:

  • Root procedures are the entrypoints the platform provides to its host (for example main_for_host).
  • Hosted procedures each carry {symbol, dispatch_index}.

LuaEmitter emits a platform-mode chunk shaped like APP = function(hosted) ... return { rt = ..., entrypoints = {...} } end.

Binding by name, not position: Native Roc dispatches hosted calls by position in an alphabetically sorted function list. The Lua output binds each hosted procedure once at load with rt.hosted(host, symbol), which looks the function up by its symbol and fails loudly if the host lacks it. That whole class of silent mismatch can't happen here.

The host: A Lua file returning { run = function(app, argv) }. LuaHost.writeProgram concatenates a shebang, the app chunk, the host chunk and the line HOST.run(APP, arg) into one runnable Lua file. run then:

  1. builds the table of hosted functions
  2. calls app(hosted) to get the runtime and the entrypoints
  3. invokes an entrypoint through rt.call_entry, which converts a Roc crash into a structured error and a Lua stack overflow into native Roc's overflow report (always a tricky business, getting errors across this line; might be incomplete)
  4. maps the outcome to the same stdout, stderr and exit status the native host would give.

hosts/default.lua (about 30 lines) is the whole host for headerless apps, mirroring default_platform/linux_runtime.zig.

Where the host comes from:

  • A host.lua next to its main.roc.
  • A platform downloaded by URL can't carry one, so the compiler fingerprints the platform's .roc files (SHA-256 over sorted names and contents) and looks up a host bundled with roc_luajit. The fingerprint describes the hosted interface, and it is identical whether the package came from the cache or a local --replace-dep copy. basic-cli 0.23.0 is matched this way, so that was the blueprint.
  • An unknown fingerprint is an error that names the fingerprint, never guessed.

Crossing the boundary: Values cross as Lua tables in a fixed layout:

  • record fields go by semantic index, which is alphabetical;
  • tag-union variants are sorted by name, as upstream's glue numbers them;
  • strings are converted in one direction only (Roc to host) by generated R.h converters chosen from the layout. An earlier version guessed by inspecting the value, and that broke once a Str could be a plain Lua number.

The host-services interface (RocOps) maps as follows:

  • alloc/dealloc disappear, because LuaJIT's GC owns memory, but the emitted code still follows every explicit reference-count statement for uniqueness and in-place reuse.
  • crashed becomes a structured error.
  • dbg and expect become runtime hooks a host can override.
  • Native resource finalizers become a drop function on a box. It fires exactly where the LIR releases the last reference, so dropping a Child kills the process and dropping a FileReader closes the file.

Effects. The basic-cli host is a port of its Rust host to LuaJIT's FFI over libc: files, directories, environment, processes, TCP sockets, SQLite and HTTP. Rust's buffering behavior is reproduced, and errno values are mapped to the same IOErr tags.

Verification. Each platform has a differential conformance suite that builds every app natively and for LuaJIT and requires identical stdout bytes, stderr bytes and exit status:

  • echo platform: all 76 buildable apps agree;
  • fx test platform: 122 of 122 IO specs agree;
  • basic-cli's own examples, as of Oct 1: 38 agree, 3 are judged by upstream's assertions alone because the native host itself segfaults on them (!!), 7 need hosted functions not yet ported, and 5 are deferred because they need helper servers or a terminal.

My own Lua platform (luajit_backend/platforms/lua) takes the opposite shape. It has one hosted function, Host.call!(op, request), carrying values encoded as LuaValue bytes, with the codec written once in Roc and once in Lua. Its native host embeds LuaJIT, so native and LuaJIT builds run the same host.lua for every effect.
